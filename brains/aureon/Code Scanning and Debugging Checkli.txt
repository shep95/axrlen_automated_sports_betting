Code Scanning and Debugging Checklist
When scanning and debugging software for security vulnerabilities, focus on the following areas:

Cross-Domain Check Bypass (A security flaw where an application's controls designed to restrict interactions between different web domains can be circumvented, potentially allowing unauthorized data access or theft. Matters here because such bypasses have been observed to facilitate data exfiltration [10]).
Examine all code paths that involve interactions between different security domains or origins.
Verify the integrity and enforcement of Same-Origin Policy (A fundamental security concept in web browsers that prevents scripts loaded from one origin from interacting with resources from another origin. Matters here as its bypass can lead to data theft [10]).
Look for improper validation or sanitization of input that could manipulate domain-related checks.
Assess the use of Cross-Origin Resource Sharing (CORS) (A mechanism that allows web servers to indicate any origin other than its own from which a browser should permit loading of resources. Matters here because misconfigurations can lead to unintended data exposure or bypasses [10]). Ensure its configuration is strict and appropriate.
Site Address Spoofing (An attack where an attacker disguises a malicious website or resource as a legitimate one, often by manipulating URLs or display information. Matters here because it can deceive users or systems into interacting with malicious content [10]).
Review all code responsible for generating, displaying, or validating URLs and site addresses.
Check for vulnerabilities in URL parsing and redirection logic.
Ensure robust validation of hostnames and origins, especially when processing external input.
Investigate how the application handles redirects and ensures the legitimacy of the target address.
Reload and Redirect Problems (Issues arising from how an application handles page reloads or redirects, which can inadvertently lead to security vulnerabilities such as information disclosure, session fixation, or bypasses of security controls. Matters here as these problems have been identified as potential attack vectors [10]).
Analyze code that triggers page reloads or redirects, particularly after user actions or authentication events.
Ensure that redirects do not expose sensitive information in URL parameters.
Verify that redirects are always to trusted, validated destinations and not to arbitrary external URLs based on user input.
Check for Open Redirect (A vulnerability where an application redirects users to an arbitrary URL specified by an attacker, often used in phishing attacks to make malicious links appear legitimate. Matters here as it is a specific type of reload/redirect problem [10]).
General Security Limit Testing (The process of actively probing an application's defenses to identify weaknesses that could allow an attacker to circumvent or exceed the intended boundaries of its security mechanisms. Matters here as it encompasses a broad approach to finding vulnerabilities [2]).
Identify areas where the application attempts to enforce security limits or access controls.
Look for logical flaws that could allow an attacker to bypass these controls [2].
Examine input validation routines for robustness against unexpected or malformed data.
Review authentication and authorization mechanisms for potential weaknesses or bypasses [2].
